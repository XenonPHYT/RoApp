What RoApp does

RoApp lets a Discord community run its applications. Staff build forms in the dashboard, applicants answer them inside Discord, and reviewers decide in a private workspace. Every community is managed separately.

Getting started (community owners)

  1. Add RoApp to your Discord server using the invite link from whoever operates this RoApp deployment.
  2. Select Sign in with Discord at the top of this page and approve access to your Discord identity and server list.
  3. Register your community. Either run /setup in your server or use Set up a community in the dashboard. Only the current server owner can do this, and Administrator permission is not enough.
  4. Open Form builder, create a form and publish it.
  5. Open Public panels (or run /panel) and publish a panel in the channel where people should apply.
  6. Review submissions in Applications or with /review.

Forms

The dashboard Form builder is the source of truth for what applicants see in Discord. A form has a title, description, instructions, requirements and 1–30 questions kept in the order you set.

Question types

  • Short text and Long text, with a character limit.
  • Multiple choice, Dropdown and Checkbox, with up to 25 choices.
  • Yes / No.
  • Number, with optional minimum and maximum.
  • Date, entered as YYYY-MM-DD.
  • Roblox username, checked for a valid format and looked up on Roblox. This confirms the account exists; it does not prove the applicant owns it.

Publishing and rules

Publishing creates a versioned form that applicants use; editing a draft never changes applications already submitted. Each form can set a cooldown between submissions and whether one person may have several active applications. Closing a form stops new submissions.

Applying in Discord

  1. Choose an application from the community’s panel or with /apply.
  2. Read the description, instructions and requirements, then select Start Application.
  3. Answer the questions. Longer forms are split into steps of up to five questions, and your answers are kept as you go.
  4. Review your answers, edit any step if needed, and select Submit Application.

Unfinished answers are kept for 24 hours so you can resume. Use /myapplications or My applications in the dashboard to follow progress, and /application withdraw to withdraw an application.

Statuses

Pending, under review, interview, revision requested, approved, rejected and withdrawn. When a status changes you are sent a private Discord message if your settings allow it; the status in My applications is always the authoritative record.

Reviewing applications

  • Work through the queue in Applications or with /review.
  • Assign reviewers to an application.
  • Add internal notes. Notes are private to staff and are never shown to applicants.
  • Approve, reject or request a revision. A reason is required, and the applicant sees only that public reason.
  • Every change is recorded in the audit history.

Access and permissions

The server owner has full dashboard access. The owner can give dashboard access to chosen Discord roles and pick which permissions each role receives:

  • Form builder, Public panels, Community settings, Staff & permissions and Audit history.
  • Applications: review, decide, add notes and assign reviewers.

Discord Administrator permission alone does not grant dashboard access. Access is checked against Discord for each community on every request, so removing a role takes effect immediately.

Slash commands

Command Purpose
/help How to use RoApp.
/setup Register this community (server owner only).
/dashboard Open the dashboard.
/apply Choose an application and start it.
/myapplications View your applications.
/application View or withdraw one of your applications.
/review Open the private review workspace (staff).
/forms List, create, publish or close forms (staff).
/panel Publish, update or remove application panels (staff).
/staff Open staff and permission settings (owner and delegated staff managers).

Signing in and sessions

The dashboard uses Sign in with Discord. You stay signed in while you use it and are asked to sign in again after a period of inactivity or when you sign out. Use the same browser for the whole sign-in. If something goes wrong, see Support.
